App Map & Reference Guide

Declutter

A container-bound, zero-token-custody Gmail cleaner with deterministic retention and 1-click disaster recovery.

System Architecture in Plain Language

Declutter executes entirely inside your private Google Workspace account via Google Apps Script (V8 runtime). It maintains state in Google Sheets (Rules and Logs tabs) and interacts directly with Gmail without third-party server token custody or external database vulnerabilities.

Reference Code Tour: The 3 Core Stops

Stop 1: Query Compilation & Injection Firewall

QueryCompiler.js → compileRule(rule)

Parses user sender patterns and preserves quoted keyword phrases (e.g., "verification code") while neutralizing operator breakouts (OR, colons :, unbalanced parentheses). Appends mandatory safety clauses (-is:starred -in:trash -in:spam -label:Declutter-Exempt).

Stop 2: Concurrency & Watchdog Loop

ExecutionEngine.js → execute() & LockManager.js

Acquires LockService.getUserLock() to prevent race conditions. Enforces the 270-second execution ceiling while querying in 100-thread chunks, tagging threads with Declutter/Trashed-RunID, and moving to trash in atomic batches of 50.

Stop 3: Deterministic 1-Click Rollback

RollbackManager.js → undoLastRun()

Locates trashed threads tagged with the active session label via in:trash label:Declutter/Trashed-RunID, restores them back to the Inbox via GmailApp.moveThreadsFromTrash() in 50-thread batches, cleans up the label, and writes RESTORED audit logs.

"To Change This, Start Here"

Change the Watchdog Ceiling or Batch Sizes

Edit Config.js: modify WATCHDOG_LIMIT_MS (default 270,000 ms), SEARCH_CHUNK_SIZE (default 100), or BATCH_TRASH_SIZE (default 50).

Change Log Rotation Threshold

Edit Config.js: modify LOG_ROTATION_THRESHOLD (default 6,000 rows) or LOG_ROTATION_PURGE_COUNT (default 1,000 rows).

Customize the Sidebar Interface

Edit Sidebar.html: all CSS and client JavaScript are self-contained without external dependencies.

A Practice to Reuse: Lazy Module Resolution in Flat Runtimes

In flat global runtimes like Google Apps Script, files are evaluated alphabetically rather than in dependency order. Eager closures (e.g. const _LockManager = LockManager) can capture variables before their file has loaded.

The reusable pattern: Use lazy runtime getters (e.g. function getLockManager() { return LockManager; }) called inside functions. This guarantees that dependencies are resolved at execution time when all files are guaranteed to be loaded and bound.
