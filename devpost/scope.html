Declutter

Decentralized, zero-token-custody Gmail inbox cleaner anchored in Google Sheets with deterministic retention rules and 1-click disaster recovery.

The Core Loop & Zero-Custody Architecture

What "Working" Looks Like (60-Second Video Demo)

The moment that conclusively proves the kernel and safety to hackathon reviewers:

1
Rule Setup & Test: User defines a rule for promo/notification emails older than 7 days and runs Dry Run to preview matched threads without modifications.
2
Live Batch Trashing: User activates live execution. Threads are tagged with Declutter/Trashed-RunID, moved to Trash in batches of 50, and logged in the Sheet.
3
1-Click Instant Undo: User clicks "Undo Last Run" in the sidebar. All trashed threads are programmatically restored back to the inbox in seconds.

Project Scope Boundaries

  • Container-Bound Google Apps Script + Google Sheet
    Runs entirely in user tenant; zero external server token custody; bypasses $15k–$75k CASA audits.
  • Structured Query Compiler
    Parses sender patterns, preserves exact phrase quotes (e.g. "verification code"), and sanitizes operator injection.
  • Execution Watchdog & Concurrency Mutex
    4.5-minute execution ceiling with 100-thread chunking; LockService prevents race collisions between cron and manual runs.
  • Deterministic 1-Click Rollback Engine
    Session-tagged labels (Declutter/Trashed-RunID) enable instant batch recovery via GmailApp.moveThreadsFromTrash.
  • Responsive Sidebar UI (PicoCSS) & Automated Trigger
    Zero-build native sidebar with 2:00 AM daily trigger setup and threshold-based log pruning at 6,000 rows.
  • Custom Label Archiving
    Allowing rules to move threads to custom archive labels rather than Gmail Trash.
  • Advanced Filter Builder in Sidebar
    Interactive UI builder for email size thresholds, attachment filters, and read/unread conditions.
  • Weekly Email Digest
    Automated email report summarizing total threads pruned and storage reclaimed.
  • Centralized Multi-Account SaaS
    Reason for Cut: Storing refresh tokens on a central server creates a high-risk honeypot and triggers mandatory $15k–$75k CASA verification audits. Container-bound architecture is strictly superior.
  • LLM Auto-Categorization
    Reason for Cut: Non-deterministic, slow, incurs API billing, and leaks user email metadata to third-party endpoints. Deterministic rules are fast, private, and free.
  • Direct Permanent Deletion (Gmail.Users.Messages.remove)
    Reason for Cut: Irreversible disaster risk. Trashing preserves Gmail's 30-day recovery buffer and makes 1-click rollback possible. Hard deletion is forbidden.
